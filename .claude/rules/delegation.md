# 委譲方針（調査・設計フェーズ）

## 原則

main（あなた）のコンテキストは有限で貴重。**調査・読解・レビューは subagent に委譲し、
main は判断・統合・ユーザー対話に集中する**。ファイル全文を main に読み込むのではなく、
subagent に要点を抽出させて結論だけ受け取る。

- 複数ファイル横断の調査・「どこにあるか分からない」探索 → subagent へ委譲
- 単一ファイル・既知箇所の 1 事実確認 → main が直接読んでよい
- 委譲した調査は二重に自分でも実行しない（結果を待つ）

## パスベースの委譲先切り替え

| 対象 | 委譲先 Agent |
|------|-------------|
| `crates/**`・コア/プラグイン実装の**読解・所在特定** | `explorer` |
| 外部仕様（crate / RFC / axum 等）の調査 | `reference-researcher` |
| `docs/spec/**`（要件・タスク・ロードマップ）の照合 | `explorer` |
| 変更差分の品質確認 | `reviewer` |
| セキュリティ・依存監査 | `security-auditor` |
| 整形・lint 違反の集計 | `linter` |

## model 配分

| 用途 | model |
|------|-------|
| 複雑な横断判断・アーキテクチャ設計 | opus または fable（fable は大規模設計・複雑な横断判断の最上位 tier） |
| 調査・生成・実装・レビュー | sonnet |
| 機械的集計・lint・ドキュメント更新 | haiku |

作成・編集フェーズの委譲は [[delegation-impl]] を参照。
