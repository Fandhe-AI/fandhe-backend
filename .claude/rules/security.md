# セキュリティ規約

本フレームワークは「AI によるセキュリティ脆弱性発見リスクに備える」ことが出発点。
攻撃表面の最小化とメモリ安全性を最優先し、変更のたびに以下を確認する。

## OWASP Top 10 の観点（バックエンドフレームワーク文脈）

- **入力検証**: HTTP パーサ・ルーティング・プラグイン入口で境界・サイズ・エンコーディングを検証する
- **認証・認可**: hub-wiring の JWT（RS256 / JWKS / JTI）・テナント境界強制・同意ゲートを迂回させない
- **インジェクション**: GraphQL・ヘッダ・ログ出力でのインジェクションを防ぐ
- **リソース枯渇（DoS）**: ボディサイズ上限・接続数・タイムアウト・スロークライアント対策
- **暗号・シークレット管理**: 鍵・トークンをコード/ログに残さない
- **可観測性**: ログに機密（トークン・PII）を出さない（[[japanese-style]] のログ方針とも整合）

## メモリ安全性

- `unsafe` は最小限・根拠明記（[[coding-rust]]）。パーサは `fuzz-runner` でファジング検証する
- `cargo audit`（既知脆弱性）・`cargo deny check`（ライセンス・出所）・`cargo geiger`（unsafe 集計）を回す

## シークレット混入防止

- API キー・トークン・パスワード・`.env` をコミット/コメント/hooks に含めない
- `settings.json` の hook `command` にシークレットやユーザー入力を展開しない

## フロー

- 実装後は `security-auditor` に監査を委譲する（[[delegation-impl]]）
- 深刻な問題は握りつぶさず main → ユーザーへ明確に報告する
- スコープ外のセキュリティ課題は [[out-of-scope-tracking]] に従い Issue 化する
