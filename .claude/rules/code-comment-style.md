# コメント規約

## 目的

後続の読み手（Claude を含む）は渡された情報からしか判断できない。
コメントはクレート・プラグイン・モジュール視点での役割と、他クレート・拡張点との文脈を
埋め込み、ファイル単体で文脈が伝わる状態にする。AI ファースト保守性の核。

## 何を書くか

- このクレート・モジュール・関数の役割と責務境界（1〜2 行要約を doc comment で）
- 呼び出し元・呼び出し先の文脈（「コアの `Middleware` から呼ばれる」「拡張点 `X` を実装する」等）
- 他クレート・拡張点との契約（trait・feature の前提条件・不変条件）
- 非自明な前提・副作用・エラー処理・`unsafe` の安全性根拠（`// SAFETY:`）

## 何を書かないか

- コードを読めば分かる逐語説明（`i += 1  // i を加算` 等）
- 陳腐化しやすい実装詳細の重複（コードと二重管理しない）

## ドキュメンテーションコメントの形式（Rust）

- クレート/モジュール入口: `//!` で 1〜2 行の役割要約
- 公開 API（関数・trait・struct）: `///` で役割・引数・戻り値・契約・feature 前提
- doc test を付けて `cargo test` で検証可能にする（AI ファースト保守性）
- feature ゲートされた API は対象 feature を doc comment に明記（[[pay-for-what-you-use]]）

コメント追加・補強の作業は `comment-code` skill を使う（実装変更はしない）。
文体は [[japanese-style]] に従う。
