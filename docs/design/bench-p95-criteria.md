# p95 基準運用（マージン・試行回数・判定不能の扱い）の見直し設計（#612）

対応: イシュー #612「p95 基準運用（マージン・試行回数・判定不能の扱い）を見直す」
（親 #608、ルート #607、Phase 1）。本文書は**設計のみ**を成果物とし、
`benches/*.sh`・workflow のコード変更は行わない（Phase 2 実装 issue #613・#614、
較正 issue #616 が実コードを担う）。

## 1. 背景と根拠データ

`benches/bench-accept.sh` の p95 基準（axum 比 `P95_RATIO_MAX=1.10`）は、共有ホスト
ではコード変更と無関係に PASS/FAIL 境界で不安定になることが
[`benches/reports/issue593-p1-zero-copy-bench.md`](../../benches/reports/issue593-p1-zero-copy-bench.md)
9 節の実測で確認されている。

- **9.1 節（外れ値）**: 静穏確認は通過したが他セッション稼働中の呼び出しで、パラメータ
  付きルート・POST の RPS が axum 比 0.6461〜0.7121（基準 >= 0.90）まで崩落する特異な
  FAIL を記録。同一バイナリの他の全試行（5.3〜5.5 節・9.2〜9.3 節）は RPS 比
  0.92〜1.08 で一貫して PASS しており、この試行のみが分布から逸脱していた。直後の
  3 コミット逐次比較（9.4 節）でも同ホスト・同バイナリ構成の崩落は再現しなかった
- **9.2〜9.3 節（隔離再計測・初回 + 自動再試行）**: 静穏な条件下でも p95 が axum 比
  1.1516〜1.2135（GET /health）・1.1696（POST /echo）まで超過し、公式ハーネス
  （`FAIL_RETRIES=1`）は 2 試行連続 FAIL で退行確定した
- **9.5 節（適用前コミットでの対照計測）**: 性能改善ツリー #579 適用**前**のコミット
  `dfca2b8` でも同一ホスト・同一ハーネス条件で p95 POST /echo 1.1025 / 1.1325 の
  2 試行連続 FAIL を記録した。これは公式ハーネスの p95 FAIL がツリーによる退行では
  なく、本ホスト + c=128 条件に内在する特性であることを示す
- **9.6 節（前後交互ペア測定、外部負荷検証なし）**: pre/cur 交互 6 ペアの直接比較で
  p95 比が -21%〜+38% の幅で振れ、符号もペア間で反転した。系統的傾向はなし
- **9.7 節（P1 区間限定・外部負荷の機械検証付き確定測定）**: #593 定義の評価区間
  （before=`655b150` / after=`1aeda06`）を pre→cur 交互 8 ペア（計 16 セッション・
  64 窓）で直接比較し、各窓の直前直後に `/proc/stat` の総 jiffies とサーバ・oha
  プロセスの `/proc/<pid>/stat` から外部 CPU 占有率を機械検証した。採用 64 窓の外部
  CPU 占有率は中央 0.73%・最大 2.45%（汚染判定しきい値 5% 超は 0 件）で、4 エンド
  ポイントすべて p95 cur/pre 比 0.980〜1.014（±2.1% 以内）に収束した

**確定結論（9 節総括、issue593 レポートより引用）**: RPS・p99・RSS・バイナリサイズ・
起動時間は非退行を確認。p95 も P1 区間の外部負荷検証付き交互測定では非退行を確認。
公式ハーネス（core vs axum 比の p95 <= 1.10 基準）の機械判定 FAIL はツリー適用前
コミットでも再現するホスト + c=128 条件のベースライン間特性であり、コード変更に
帰属しない。

## 2. 現行運用の整理

- **判定 3 値**: PASS（`bench-accept.sh` exit 0）/ FAIL（exit 1、非決定的な計測 FAIL
  専用）/ BLOCKED（exit 2、専有ロック取得不能・ビルド失敗・静穏未達・baseline /
  `CORE_BIN` バイナリ未整備等の決定論的な環境失敗。`benches/README.md` 592〜625 行、
  イシュー #478/#479）
- **再試行契約**（`benches/lib/exclusive.sh` の `nfr6_run_with_fail_retry`、
  `FAIL_RETRIES`）: FAIL のみ再試行・PASS は再試行しない・BLOCKED は再試行しない・
  週次 schedule は `FAIL_RETRIES=1`（2 連続 FAIL で退行確定）
- **週次ベンチ自動起票**（`.github/workflows/bench-schedule.yml`、
  `docs/design/bench-scheduled-run.md`）: 非 0（FAIL または BLOCKED）終了で
  `bench-regression` ラベルの Issue を自動起票。タイトルで FAIL/BLOCKED を区別
- **専有実行枠プロトコル**（`docs/design/nfr6-exclusive-measurement.md`）: flock に
  よる相互排他・`wait_for_quiescence` による静穏確認・環境スナップショット。本設計は
  この専有実行枠プロトコル自体を変更しない

現行運用の限界: 「FAIL 判定不能な外因（一時的な外部負荷）」と「コード起因の真の
退行」を区別する機構が判定ロジック側になく、9.1〜9.7 節の切り分けはすべて人間による
事後の個別レポート作業（隔離再計測・逐次比較・交互ペア測定・外部負荷プローブの
その場実装）に依存していた。

## 3. 判定 4 値化（判定不能の導入）

現行の PASS / FAIL / BLOCKED に **INCONCLUSIVE（判定不能）** を追加する。

| 判定 | 終了コード | 意味 |
|------|-----------|------|
| PASS | 0 | 全指標が基準を満たす |
| FAIL | 1 | 非決定的な計測結果が基準を満たさない（退行の可能性が高い） |
| **INCONCLUSIVE** | **3（暫定提案）** | **計測は完走したが、結果がノイズ帯域内に留まり退行の有無を確定できない** |
| BLOCKED | 2 | 計測環境自体が壊れている（環境起因の判定不能。既存契約を変更しない） |

INCONCLUSIVE と BLOCKED は区別する。BLOCKED は「計測そのものが成立しなかった」
（バイナリ欠如・ビルド失敗等）状態であり、既存の非再試行・fail-closed 契約を維持する。
INCONCLUSIVE は「計測は成立したが判定を確定できない」状態であり、2.4 節・2.5 節の
手続きに委ねる。

### 3.1 fail-closed 動作（不変条件）

- INCONCLUSIVE を PASS へ丸めない
- INCONCLUSIVE のまま自動マージしない（`.claude/rules/feature-modification.md` の
  完遂判定 3 条件・`ci-complete` 緑の対象外として扱う）
- 週次ベンチの自動起票（`bench-regression` ラベル）は FAIL/BLOCKED と同様に
  INCONCLUSIVE も対象とし、ジョブは赤のまま維持する。タイトルで「判定不能（要再計測）」
  として FAIL（退行確定）・BLOCKED（計測不能）と区別する（Phase 2 #614 へ引き渡し）
- 確定には再計測（4 節の二次判定モード）を要する。二次判定が実行できない場合は
  一次判定のまま確定せず、INCONCLUSIVE のまま留める

## 4. しきい値マージンと判定帯

**spec の基準値そのもの（p95 axum 比 <= 1.10、`docs/spec/04-requirements.md` 由来）は
変更しない**（`docs/design/README.md` の「`docs/spec/` を書き換えない」規約）。運用
判定の層でのみ帯域を追加する。

一次判定（axum 比）を 3 帯域に分割する。

| 帯域 | 条件 | 一次判定 |
|------|------|---------|
| PASS | 比 `<= 1.10` | PASS 確定 |
| 判定不能帯 | `1.10 < 比 <= 1.10 × (1 + M)` | INCONCLUSIVE（二次判定へ） |
| FAIL 候補 | 比 `> 1.10 × (1 + M)` | FAIL 候補（二次判定へ） |

マージン `M` は**確定値（0.10、#616 のホステッドランナー較正ラン（固定 ref・
同一コミット 797245a5 で mode=primary × 5・mode=pair × 2、全ラン success・
総合 PASS）で帯域内判定を実測確認のうえ確定。値の変更なし。判定不能帯
1.10〜1.21 への突入は較正ラン中に未観測）**とする。根拠となる実測分布:

- 9.5 節（適用前コミットの境界 FAIL）: 比 1.1025〜1.1325（基準比 +0.2%〜+3.0%）
- 9.2〜9.3 節（適用後の FAIL）: 比 1.1199〜1.2135（基準比 +1.8%〜+10.3%）
- 9.7 節（クリーン条件の交互測定、真の差）: cur/pre 比 0.980〜1.014（±2.1% 以内）

`M = 0.10`（判定不能帯の上限を axum 比 1.21 相当とする）を確定値として採用すると、9.5 節の
全試行と 9.2〜9.3 節の一部（1.1199〜1.2135 のうち 1.21 以下）が判定不能帯に収まり、
9.7 節のクリーン測定（±2.1%）は帯域の外側（PASS 側）に十分な余裕を持って収まる。
9.2〜9.3 節の 1.2135 のように帯域上限をわずかに超える値が残る点は、#616 の較正により
`M` を再検討する際の入力とする。

適用対象は **p95 に限定**する。RPS・p99・RSS・バイナリサイズ・起動時間の判定は現行
（単一しきい値・PASS/FAIL 二値）を維持する。9 節の実測でこれらの指標は一貫して PASS
しており、p95 のような不安定性は確認されていないため、判定帯の導入対象を広げる根拠が
ない。

## 5. 必要試行数と多数決・二次判定（交互測定）への接続

### 5.1 一次判定の多数決化

現行「初回 + FAIL 時 1 再試行（2 連続 FAIL で退行確定）」を**最大 3 試行の多数決**へ
拡張する。

- 初回 PASS は即確定（現行の「PASS は再試行しない」契約を維持）
- 初回が FAIL 候補または判定不能帯なら追加試行する
- 3 試行中 2 試行以上が同一判定（PASS / FAIL 候補 / 判定不能帯のいずれか）に達したら
  その判定で確定する
- 3 試行が PASS・FAIL 候補・判定不能帯に割れる、または判定不能帯に滞留する場合は
  INCONCLUSIVE とする
- **6.1 節の (a) のみ該当試行との関係**: いずれかの試行が 6 節の除外条件 (a)（分布
  逸脱）のみに該当し (b)（外因の独立証拠）を欠く場合、当該試行は本節の多数決対象
  （PASS / FAIL 候補 / 判定不能帯のいずれか）として扱わない。6.1 節の規約どおり
  当該試行は常に INCONCLUSIVE として扱い、**他の試行が PASS 多数であっても多数決で
  上書き（PASS 確定）しない**。試行系列全体を INCONCLUSIVE のまま 5.2 節の二次判定へ
  委ねる（PR #617 レビュー指摘 P0 対応。断続的な真の退行が「3 試行中 1 回だけ発現」
  という理由だけで多数決により PASS へ救済されることを防ぐ）

### 5.2 二次判定（交互測定）への接続

一次判定（axum 比）が FAIL 候補または判定不能帯の場合、**確定手段は before/after
交互ペア測定（#613 で実装する二次判定モード）に委ねる**。9.7 節の外部負荷機械検証
付き交互測定が、9.6 節の名目しきい値超過（外部負荷検証なし）を非退行と確定できた
実例が根拠である。

一次判定（axum 比）と二次判定（cur/pre 比）は尺度が異なり、一次判定の帯域
（4 節、マージン `M`）をそのまま二次判定の合否基準に流用できない。二次判定は
以下を独立した基準として定義する（**すべて確定値**。#616 のホステッドランナー
較正ランで確定し、9 節の引き渡し一覧に含める。`M2` は実測確認のうえ確定、
最低ペア数等の較正ラン中に発火しなかった経路は fail-closed 原則により現行値の
まま確定 — 区分は `benches/reports/issue616-hosted-runner-calibration.md`
11 節参照）。

- **比較対象・統計量**: 同一 before/after コミット対を交互配置した各ペアの p95
  について、cur（after）/pre（before）比を算出し、**採用ペア全体の中央値**を
  最終統計量とする（9.7 節と同じ「交互測定 + 中央値評価」方式。個々のペアの
  ばらつきに判定を左右されないため）
- **必要ペア数（暫定 6 ペア以上）**: 9.7 節の実測（8 ペア・64 窓）を安全側に
  切り下げた値。6 ペア未満しか確保できない場合は次項の INCONCLUSIVE 条件に従う
- **非退行しきい値 `M2`（暫定 0.05、cur/pre 比換算で上限 1.05）**: 9.7 節の
  クリーン測定で観測された真の差 cur/pre 0.980〜1.014（±2.1% 以内）を安全側
  マージンとして包含しつつ、一次判定のマージン `M`（暫定 0.10）より小さい値
  とする（二次判定は一次判定より解像度の高い外部負荷検証を伴うため、より
  タイトな基準を課せる）
- **PASS/FAIL/INCONCLUSIVE の境界**:
  - PASS: 採用ペア数 `>= 6` かつ 中央値 `cur/pre <= 1 + M2`（暫定 `<= 1.05`）
  - FAIL: 採用ペア数 `>= 6` かつ 中央値 `cur/pre > 1 + M2`（暫定 `> 1.05`）
  - INCONCLUSIVE: 採用ペア数が最低ペア数（暫定 6）を下回る場合（外部 CPU
    占有率汚染（6 節 (b)、暫定 > 5%）によるペア除外後の不足を含む）。この場合も
    5.2 節冒頭の原則どおり **一次判定のまま確定しない**
- **算出対象範囲**: cur/pre 比が下回る側（cur/pre < 1、性能改善方向）は非退行と
  みなし PASS 側として扱う。上限のみを合否境界とし、下限は設けない（本設計の
  目的は退行検知であり、改善側の逸脱を FAIL 扱いにする必要がないため）

上記の数値パラメータ（必要ペア数 6・非退行しきい値 `M2` = 0.05）は、#616 の較正ランで
実測に基づき確定済み（値の変更なし）。

## 6. 外れ値の客観的除外条件

9.1 節で人間判断により除外した外れ値（RPS 比 0.65〜0.71 への崩落）の判定根拠のうち、
分布逸脱の定量化（(a)）を機械検証可能な条件として定式化する。ただし外因の証拠
（(b)）は、9.1 節で採用した「直後の再計測で再現しない」という根拠を**そのままは
機械条件へ昇格させない**（下記 (b) 参照）。独立した機械的証拠を欠く単発の非再現は、
断続的な真の退行との区別がつかないため、除外条件ではなく 5 節の多数決・二次判定に
委ねる設計へ変更した（PR #617 レビュー指摘 P0 対応。9.1 節自体の機械的除外可否は
7 節の机上検証で扱う）。

除外可能なのは **(a) かつ (b)** の両方を満たす試行のみ。

- **(a) 分布逸脱**: 当該試行の指標比が、同一バイナリ・同条件の他の採用試行群の
  中央値から一定割合（**暫定 25%**）以上逸脱している
  - 実値照合: 9.1 節の外れ値（RPS 比 0.6461〜0.7121）を、他試行の分布（RPS 比
    0.92〜1.08）から想定される中央値の両端（0.98・1.00）それぞれに対して個別に
    算出すると、逸脱は次のとおりである。

    | 外れ値 | 中央値 1.00 との逸脱 | 中央値 0.98 との逸脱 |
    |--------|----------------------|----------------------|
    | 0.6461 | 35.39% | 34.07% |
    | 0.7121 | 28.79% | 27.34% |

    最小値（0.7121・中央値 0.98 の組み合わせ）でも 27.34% であり、しきい値
    30% では条件を満たさない。閾値を実測レンジの下限（27.34%）に安全マージンを
    加えた **暫定 25%** へ較正することで、想定される中央値のいずれの組み合わせ
    でも 9.1 節の外れ値全域（0.6461〜0.7121）が条件を満たす。この 25% も
    #616 の較正ランで実測に基づき確定済み（値の変更なし）
- **(b) 外因の証拠**: 外部 CPU 占有率プローブ（#613 実装、9.7 節の手法を一般化した
  もの）が汚染（**暫定 > 5%**）を記録している **場合に限り成立する**。プローブに
  よる独立した機械的証拠のみを除外根拠として採用し、「直後の再計測で逸脱が
  再現しない」ことは単独では (b) を満たさない
  - 再現しないことを exclusion 根拠に含めない理由: 非再現は外因（一時的な外部
    負荷）と断続的な真の性能退行（負荷条件に依存して発現する回帰等）のどちらでも
    起こりうるため、両者を区別する独立した証拠にならない。これを OR 条件として (b) に
    含めると、単発の非再現だけで (a) を満たす FAIL 試行を機械的に除外できてしまい、
    既存の fail-closed な退行検知が fail-open になる（PR #617 レビュー指摘 P0 対応）
  - 実値照合: 9.7 節の採用窓は外部 CPU 占有率が最大 2.45%（< 5%）であり、これらは
    除外対象にならず全て採用される（除外条件が過剰にクリーン測定を弾かないことの
    確認）
  - 独立証拠（プローブによる汚染記録）が得られず、かつ (a) の分布逸脱のみが
    観測される場合は、除外せず **INCONCLUSIVE** として二次判定（5 節の交互測定）
    に回す。「非再現」という事実そのものは無視せず、二次判定のトリガー・レポート
    上の参考情報として記録する（6.1 節）

### 6.1 除外時の fail-closed 規約

- 除外は必ずレポート（`REPORT_MD`）へ記録する。**silent drop は禁止**（除外した
  試行の生値・除外理由・(a)(b) の判定根拠を残す）
- 除外後の採用試行数が最低試行数（5.1 節の多数決に必要な数）を下回る場合は
  INCONCLUSIVE とする
- (a) のみ該当し (b)（プローブによる汚染記録）が不成立の試行は除外しない。ただし
  6 節の方針どおり、当該試行を通常の PASS/FAIL 候補・判定帯評価の対象には含めず
  **常に INCONCLUSIVE** として扱う（判定帯上の位置（判定不能帯に収まるか否か）に
  よって PASS/FAIL へ分岐させない）。分布逸脱が疑われるが独立証拠を欠く旨をレポート
  へ記録した上で、5.1 節の多数決対象からも除外し、5.2 節の二次判定（交互測定）で
  確定する（PR #617 レビュー指摘 P0 対応。6 節の「(a) のみ該当は一貫して INCONCLUSIVE」
  という方針と本節・7 節・9 節の記述を統一する）

この机上検証により、(1) 9.1 節の外れ値は独立した外因証拠を欠くため除外条件では
機械的に除外されず、かつ 6.1 節改訂後の規約により常に INCONCLUSIVE として扱われ
5.1 節の多数決対象（他試行群による PASS/FAIL 集計）からも外れるため、断続的な真の
退行が他試行の PASS 多数によって誤って希釈・PASS 化されない、(2) 9.7 節のクリーン
測定は判定帯・除外条件のいずれにも誤って弾かれず PASS を通り、(3) 9.5 節の境界
FAIL は「誤 FAIL」ではなく INCONCLUSIVE として二次判定へ回る設計になっていることを
確認した。除外条件 (a)+(b) は「独立した機械的証拠を伴う逸脱」のみを対象とする狭い
機構であり、それ以外の分布逸脱（(a) のみ該当）は多数決に委ねず一貫して INCONCLUSIVE

が、この机上検証で明確になった（PR #617 レビュー指摘 P0 対応。6 節・6.1 節・7 節・

## 11. セキュリティ考慮（OWASP Top 10 観点）

- **フェイルクローズの維持・強化**: INCONCLUSIVE を PASS へ丸めない・外れ値除外の
  silent drop 禁止・除外後の試行数不足は INCONCLUSIVE・二次判定不能時も確定しない、
  という fail-closed 原則を本設計の不変条件とする（判定緩和による性能退行=リソース
  枯渇（DoS）耐性低下の見逃し防止、`.claude/rules/security.md`）
- **基準の実質的弱体化の防止**: spec 基準値 1.10 は不変とし、マージンは「FAIL を
  判定不能へ倒す」方向にのみ作用させる（判定不能帯を PASS 扱いにしない）。しきい値・
  マージンは #616 の実測較正まで暫定と明記し、根拠なき緩和を許さない
- **機密情報の非混入**: 本文書へホスト固有情報（ホスト名・ユーザー名・トークン・
  scratchpad 絶対パス）を記載していない。引用した計測データは既にリポジトリ内
  レポート（issue593）に公開済みの数値のみ
- **インジェクション観点（Phase 2 への引き渡し）**: env 経由パラメータ（マージン `M`
  等）を追加する際は `bench-accept.sh` 既存の `validate_numeric` による数値検証を
  必須とする旨を 9 節の引き渡し一覧に明記した
- **CI 権限**: 本イシューでは workflow を変更しない。#614 への引き渡しに
  「`permissions` 最小権限・fork PR へのシークレット非露出の現行構成を弱めない」旨を
  含める（`.claude/rules/ci.md`）
