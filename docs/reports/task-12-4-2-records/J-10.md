# 対応可否判定記録

docs/design/feasibility-guardrail.md の判定規約に従う判定記録。
`scripts/feasibility-check.sh --input <このファイル>` で形式検証できる。

## 判定区分

不可（明確な拒否）

## 該当カテゴリと判断根拠

「明確な脆弱性を招く要求」カテゴリに該当する。要求はユーザー入力の文字列をそのまま SQL
クエリに文字列結合して実行するというものであり、SQL インジェクション（CWE-89、OWASP
Top 10 A03:2021-Injection）に直結する実装を明示的に求めている。3 軸のうち「安全か」が
不充足（[[security]] の入力検証・インジェクション防止方針と正面から衝突する）。実施可能
性・影響範囲以前に、安全性の軸が明白に満たされないため着手不可と判定する。

## 要人間判断事項

本来の目的（動的な検索条件・フィルタ構築など）を確認したい。要求の背景にある正当なユー
スケースが分かれば、パラメータ化クエリ（プレースホルダ + バインド）を用いた安全な代替実
装を設計できる。

## 代替案

SQL 実行が必要な場合は、文字列結合ではなくパラメータ化クエリ（プリペアドステートメント・
バインドパラメータ）を使う。Rust では `sqlx` の `query!`/`query_as!` マクロや `query()` +
`.bind()` のように、ユーザー入力を SQL 文字列に直接埋め込まず別チャネルで渡す機構を用いる
のが標準的な対策である。必要であれば、この代替方式での実装要求として受け入れ基準を明確化
した上で再度依頼してほしい。
