# 対応可否判定記録

docs/design/feasibility-guardrail.md の判定規約に従う判定記録。
`scripts/feasibility-check.sh --input <このファイル>` で形式検証できる。

対象要求: 「`plugin-tracing` のサンプリングレートを外部から設定変更できるように
してほしい。ただし CI や既存ベンチマーク（PoC-10）への影響はまだ確認していない。」

## 判定区分

条件付き可

## 該当カテゴリと判断根拠

なし（不可 4 カテゴリのいずれにも該当しない）。

実コード調査の結果、サンプリングレートは既に設定可能な構造として実在する。
`crates/plugin-tracing/src/config.rs` の `TracingConfig::sample_interval`
（`NonZeroU64`、既定 100）が `TracingConfig::new` で指定でき、
`crates/core/src/server.rs:463` の `Server::tracing(config)`（`tracing` feature
限定 API）経由で `TracingLayer` → `Sampler`（`sampler.rs`、決定的カウンタ方式）
に渡る。したがって「未定義依存」型ではなく、既存機構の設定入口を外部化する
延長線上の改修であり、依存の性質・方式が未選定という状況にはない。

安全性方針との衝突もない。サンプリングレートの変更は
`.claude/rules/security.md` の DoS 耐性・境界検証・可観測性の各方針を後退させ
ない。値の下限（ゼロ）は `NonZeroU64` により型レベルで排除済みで、外部入力を
受ける場合もこの型でパースすれば同じ不変条件を維持できる。

不充足なのは 3 軸のうち「実施可能か」の 1 軸のみである。要求文中の「外部から」
が指す設定手段（環境変数 / 設定ファイル / 実行時 API のいずれか）が未指定で、
かつ要求者自身が明示するとおり CI・PoC-10 ベンチマークへの性能影響が未検証で
ある。いずれも具体的な選択肢・検証手順の一点として着手条件に書き下せるため、
6.1 節の「条件付き可」成立条件（不充足軸が 1 軸のみ・欠落が 1 点として列挙可能・
補完後に他軸へ新たな不確定が生じない）をすべて満たす。

## 着手条件

以下を確定・確認してから着手する。

1. **設定手段の確定**: 「外部から」の具体手段を、(a) 環境変数、(b) 設定ファイル、
   (c) 既存 `Server::tracing(TracingConfig)` の公開 API 拡張、のいずれかに
   一意に確定する。実行時の動的変更（起動後のホットリロード）を含むか否かも
   併せて確定する。`Sampler` は現状 `interval` を不変フィールドとして保持する
   ため、動的変更を含む場合は内部構造の変更範囲が変わる。
2. **性能退行の確認手順の確定と実施**: PoC-10 の測定条件で
   `benches/` のトレーシング性能計測（`benches/reports/task-10.4-tracing-performance.md`
   の再現手順）を実装前後で再実行し、RPS 退行が許容範囲内であることを確認する。
   許容範囲の閾値（例: 退行 X% 以内）を着手前に数値で確定する。
   NFR-6 相当の判定を要する場合は `benches/nfr6-exclusive.sh` の専有計測枠を使う。
3. **CI 影響の確認**: `ci-complete` の対象ジョブ（fmt / clippy / test / doc）に
   加え、feature 無効構成で新規依存が `cargo tree` に出ないこと
   （`.claude/rules/pay-for-what-you-use.md`）を確認する。設定手段に (a) や (b)
   を選ぶ場合、パーサ依存の追加要否と `docs/dep-impact/records.md` への記録が
   必要になるため、この点を条件 1 の確定と併せて判断する。

上記 3 点はいずれも値・選択肢・検証手順の確定であり、確定後の再判定で
「安全か」「影響範囲が許容内か」に新たな不確定は生じない見込みである。

## ユーザー承認

## 3 軸判定結果

### 実施可能か

不充足（1 軸）。改修対象（`TracingConfig::sample_interval`）と目的は明確だが、
「外部から」の設定手段が未指定で、受け入れ基準に必要な性能退行の許容閾値も
未確定。着手条件 1・2 の確定により検証可能な受け入れ基準へ落とせる。

### 安全か

充足。サンプリングレートの外部設定化は `.claude/rules/security.md` の既存方針
（DoS 耐性・入力検証・可観測性・機密非出力）を後退させない。値のゼロ除算は
`NonZeroU64` で型レベル排除済みであり、外部入力経路でも同型でパースすることで
不変条件を維持できる。サンプリング間隔を極端に大きくした場合の可観測性低下は
運用上の設定判断の範囲であり、安全性方針そのものへの抵触ではない。

### 影響範囲が許容内か

充足。影響は `crates/plugin-tracing`（`config.rs` / `sampler.rs` / `layer.rs`）と
`crates/core` の `tracing` feature 限定 API（`server.rs:463` 付近）に限定され、
特定可能。`tracing` feature 無効時は `#[cfg(feature = "tracing")]` により
コード・依存とも従来どおり完全に除外される。利用者影響は
`TracingConfig` の公開 API 追加（後方互換を保てる形での拡張）に留まる。
