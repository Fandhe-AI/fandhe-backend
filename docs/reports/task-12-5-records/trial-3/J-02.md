## 該当カテゴリと判断根拠

不可 2 区分には該当しない（判定区分が「条件付き可」のため本節は適用対象外だが、判断根拠として記録する）。

`crates/plugin-tracing/src/layer.rs` の `TracingLayer::record_response(&self, head: &RequestHead, elapsed: Duration)` は、呼び出し元であるコアの `Middleware::on_response(&self, head: &RequestHead, elapsed: Duration)`（`crates/core/src/extension.rs`）からステータスコードを一切受け取っていない。`crates/core/src/server.rs` のリクエスト処理ループ（745〜754 行目、815〜845 行目付近）では `Response` オブジェクト（ステータスコード保持）が `on_response` 呼び出し時点で既に生成済みだが、`Middleware` trait のシグネチャにステータスコードを渡す引数がないため、現状の trait 契約のままでは要求を満たせない。

`Middleware` は AGENTS.md が明記する 3 種の正式拡張点（`Middleware` / `UpgradeHandler` / `RequestGate`）の一つであり、契約変更の手順が AGENTS.md に定義されている。実装するには `Middleware::on_response` のシグネチャ変更（ステータスコード引数の追加）という、`crates/plugin-tracing` 単体に閉じない**拡張点契約への破壊的変更**が必須になる。これは要求文面が示す「`plugin-tracing` のログ出力の追加」という見た目のスコープを超え、着手前に人間の意思決定（契約変更を許容するか、非破壊的な代替手段を採るか）を要する。

## 要人間判断事項

- `Middleware::on_response` のシグネチャを破壊的に変更する（`head`・`elapsed` に加えてステータスコード、または `&Response` 全体を渡す等）ことを許容するか
- 破壊的変更を許容する場合、影響を受ける全実装（`crates/core/src/server.rs` の `TracingMiddleware` および内蔵テストモック、`crates/core/src/extension.rs` のドキュメント例・テストモック、将来の外部 `Middleware` 実装者）への周知・移行方針
- AGENTS.md の拡張点変更手順（136 行目以降）に従った変更起票が必要かどうか

## 代替案

- （破壊的変更を避ける場合）ステータスコードを渡さない範囲での代替、例えば `Response` 生成側で別途ログ出力する専用フックを新設するなど、既存の `Middleware::on_response` 契約を変更しない設計を別途検討する
- 破壊的変更を許容する場合は `feat!:`（Breaking Change）として明示し、`.claude/rules/conventional-commits.md` の Breaking Change 記法に従ってコミット・PR を作成する

## 着手条件

- 上記「要人間判断事項」について人間の判断・承認を得ること（`Middleware::on_response` のシグネチャ破壊的変更を許容する、または代替設計を指示する）
- 承認内容に応じて、影響範囲（`crates/core/src/extension.rs`・`crates/core/src/server.rs`・`crates/plugin-tracing/src/layer.rs`、および関連テスト・doc）を確定してから着手する
- 着手前に本規約の 3 軸（実施可能か・安全か・影響範囲が許容内か）を再判定する

## 3 軸判定結果

### 実施可能か

（条件付き可のため本節は必須ではないが、参考として記載）検証可能な受け入れ基準（レスポンス処理後の tracing イベントに `status` フィールドが追加され、`record_response` 呼び出し時の既存テストパターン（`layer.rs` の `#[cfg(test)]` 内のイベント検証）に準じて確認できる）に落とせる。ただし現行の `Middleware::on_response` シグネチャのままでは実現不能であり、シグネチャ変更を前提とした場合にのみ実施可能。

### 安全か

（参考記載）ステータスコードは `.claude/rules/security.md` が禁じる機密情報（トークン・PII・ヘッダ値・ボディ・クエリ文字列）に該当せず、記録対象を拡張しても OWASP Top 10・ログインジェクション観点との衝突はない。安全性方針との衝突（不可カテゴリ）には該当しない。

### 影響範囲が許容内か

（参考記載）`impl Middleware for` は workspace 内で `crates/core/src/server.rs` と `crates/core/src/extension.rs` の 2 箇所のみと特定済みであり、影響先は列挙可能で限定できる。ただし「単一クレート（plugin-tracing）内の変更」という要求文面の想定スコープを超え、正式拡張点（`Middleware`）の契約変更を伴う点は着手前に明示的な承認を要する。
